# Граф ROS 2 и анализ сбоя

## Состояние 1: Исправный граф (домен 16)

### Ноды:
- `/turtlesim` - симулятор черепахи
- `/teleop_turtle` - управление с клавиатуры

### Топики:
- `/turtle1/cmd_vel` (geometry_msgs/msg/Twist) - команды движения
- `/turtle1/color_sensor` (turtlesim/msg/Color) - датчик цвета
- `/turtle1/pose` (turtlesim/msg/Pose) - текущая поза
- `/rosout` (rcl_interfaces/msg/Log) - логи

### Измерения:
- Частота публикации `/turtle1/pose`: ~60 Hz (неподвижная черепаха)
- После нажатия ↑ координаты изменяются: x, y, theta

## Состояние 2: Разрыв связи (teleop в домене 17)

### Наблюдения:
- `ros2 node list` в домене 17 показывает только `/teleop_turtle`
- Нода `/turtlesim` не видна (осталась в домене 16)
- При нажатии ↑ черепаха НЕ двигается
- Чтение `/turtle1/pose` из домена 16 показывает неизменные координаты

### Причина:
ROS_DOMAIN_ID определяет multicast-группу DDS. Ноды с разными ID изолированы друг от друга на сетевом уровне.

## Состояние 3: Восстановление (возврат в домен 16)

### Наблюдения:
- `ros2 node list` снова показывает обе ноды
- При нажатии ↑ черепаха двигается
- Координаты в `/turtle1/pose` изменяются

## Вывод

Сбой воспроизведён: команды управления не доставлялись из-за несовпадения ROS_DOMAIN_ID.
Корневая причина: изоляция multicast-доменов DDS.
Доказательство исправления: после возврата в домен 16 управление восстановилось.
